# bookin

> Built with [Claude Code](https://claude.ai) + [opencode](https://opencode.ai)

Drop ebooks into a folder — bookin automatically fetches metadata and cover art from the [Hardcover](https://hardcover.app) API, then organizes them into a structured output folder using a pattern you define. [Calibre](https://calibre-ebook.com) handles the embedding and the template-driven export.

## How it works

1. Drop an ebook (`.epub`, `.mobi`, `.azw3`, `.pdf`, etc.) into the input folder
2. bookin detects the new file, reads its embedded metadata, and queries the Hardcover API for enriched metadata + cover
3. The book is exported to the output folder using your configured template (e.g. `{authors}/{title}`)
4. The source file is removed from the input folder

Files that fail are moved to `input/_failed/` with an `.error` sidecar describing what went wrong. They stay out of `output/`, which holds only the finished library, and the watcher ignores that folder — so a failed book is never retried automatically. Fix whatever the sidecar reports and move the file back into `input/` to try again.

## Quick start (Docker)

```bash
# 1. Create local folders
mkdir -p input output

# 2. Set your Hardcover API token (required) in a .env file
echo "BOOKIN_HARDCOVER_TOKEN=your-token-here" > .env

# 3. Start
docker compose up -d

# 4. Drop an ebook in
cp my-book.epub input/
```

Output appears in `./output/` organized by your template.

## Configuration

Configuration is done via environment variables:

| Variable | Default | Description |
|---|---|---|
| `BOOKIN_HARDCOVER_TOKEN` | _(required)_ | Hardcover API token; validated at startup |
| `BOOKIN_TEMPLATE` | `{authors} - {title}` | Output path template |
| `BOOKIN_LOG_LEVEL` | `INFO` | Log level (`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`) |
| `BOOKIN_INPUT_DIR` | `/input` | Directory watched for new ebooks |
| `BOOKIN_OUTPUT_DIR` | `/output` | Directory organized output is written to |

`BOOKIN_HARDCOVER_TOKEN` is required — the daemon makes one authenticated call to Hardcover at startup and exits with a clear error if the token is missing or rejected.

Set them in the `environment:` section of `docker-compose.yml`. The token is
kept out of the file and read from a `.env` (not committed):

```yaml
environment:
  - BOOKIN_HARDCOVER_TOKEN=${BOOKIN_HARDCOVER_TOKEN}   # from .env
  # - BOOKIN_TEMPLATE={authors} - {title}
  # - BOOKIN_LOG_LEVEL=INFO
```

The `BOOKIN_TEMPLATE` field uses [Calibre Template Language](https://manual.calibre-ebook.com/template_lang.html) — the same syntax as Calibre's own "Save to disk" feature.

**Common fields:**

| Field | Example |
|---|---|
| `{authors}` | `Frank Herbert` |
| `{title}` | `Dune` |
| `{series}` | `Dune Chronicles` |
| `{series_index}` | `1` |
| `{publisher}` | `Ace Books` |
| `{pubdate}` | `1965` |

**Template examples:**

```
# Author / Title
{authors}/{title}

# Author / Series N - Title
{authors}/{series}/{series_index} - {title}

# Flat: Author - Title
{authors} - {title}
```

## Local development

**Prerequisites:** [`uv`](https://docs.astral.sh/uv/getting-started/installation/), [Calibre](https://calibre-ebook.com/download)

```bash
# Install Calibre (macOS)
brew install --cask calibre

# Install Python dependencies
uv sync

# Generate the Hardcover client (required — it is not committed)
make codegen

# Run daemon (watch /input continuously)
uv run bookin

# Debug logging
uv run bookin --verbose
```

### The Hardcover client

`src/bookin/graphql_client/` is generated by [ariadne-codegen](https://github.com/mirumee/ariadne-codegen) from Hardcover's schema and the operations in `queries/`.

The schema comes from the [hardcover-docs](https://github.com/hardcoverapp/hardcover-docs) submodule at `vendor/hardcover-docs`, pinned to a commit so the generated client is reproducible. You don't need `git clone --recursive`: `make codegen` initialises the submodule if it's missing. `make update-schema` moves the pin to upstream's latest and regenerates — commit the submodule bump with whatever the new client requires.

It is **not committed** — it's built on demand. `make codegen` produces it, and `make test`/`lint`/`typecheck`/`check` depend on it, so it regenerates automatically whenever the schema or a query changes. CI and the Docker build generate it too. A fresh clone needs `make codegen` (or any `make` target that depends on it) before `uv run bookin` will import.

Change a `.graphql` file rather than the output. Codegen validates the operations against the schema, so a query that no longer matches fails loudly.

The pin means the schema can lag Hardcover. If upstream renames a field we select, lookups start failing and each book logs `Hardcover lookup failed: ...` naming the field, before falling back to its embedded metadata. Run `make update-schema` when that happens.

## Commands

**Development:**
```bash
make test       # run tests
make lint       # lint
make format     # format
make typecheck  # type check
make check      # all of the above (lint + format + types + tests)
make fix        # auto-fix lint and formatting
make codegen        # regenerate the Hardcover client
make update-schema  # bump the pinned Hardcover schema, then regenerate
```

**Docker:**
```bash
make build      # build image
make up         # start daemon (watches ./input/)
make down       # stop
make logs       # follow logs
```

## Docker volume mounts

| Mount | Purpose |
|---|---|
| `./input:/input` | Drop ebooks here |
| `./output:/output` | Organized output |

Input and output paths are fixed to `/input` and `/output` inside the container.
